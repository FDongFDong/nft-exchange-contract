# NFT Exchange Contract (EIP-712 · EIP-2612)

ERC-20 토큰으로 NFT를 사고파는 거래소 컨트랙트입니다. 판매자는 오프체인 주문에 서명하고, 구매자는 Permit 서명 하나로 approve 없이 한 번의 트랜잭션에 구매합니다.

굿블록 재직 중(2025.09 ~ 2025.10) 직접 설계하고 작성해 BSC 테스트넷에 배포했습니다. 이 저장소의 `src/Exchange.sol`은 배포한 버전과 같은 파일입니다.

- 배포 주소 (BSC Testnet): [`0x8AE469E8dE6d031B5915104343Ea49B2A32A6608`](https://testnet.bscscan.com/address/0x8AE469E8dE6d031B5915104343Ea49B2A32A6608#code)
- 컴파일 환경: Solidity 0.8.27, OpenZeppelin Contracts 5.4.0

## 왜 만들었나

기존 구매 흐름은 `approve`와 거래 두 번의 트랜잭션이 필요했습니다. 사용자는 가스를 두 번 내고, 첫 트랜잭션이 확정될 때까지 기다려야 했습니다.

이 컨트랙트에서는 구매자가 EIP-2612 Permit에 오프체인으로 서명하면 `fill` 안에서 `permit`과 거래를 함께 처리합니다. 구매 트랜잭션이 2회에서 1회로 줄었습니다.

## 거래 흐름

1. 판매자가 EIP-712 형식의 판매 주문에 서명합니다(오프체인, 가스 없음).
2. 구매자가 결제 토큰에 대한 Permit에 서명합니다(오프체인, 가스 없음).
3. 구매자(또는 대행자)가 `fill`을 호출합니다.
4. 컨트랙트가 주문 서명을 검증하고 nonce를 사용 처리합니다.
5. Permit을 실행한 뒤 대금을 정산하고 NFT를 옮깁니다.

## 보안 장치

| 위협 | 대응 |
|---|---|
| 재진입 | 상태를 먼저 바꾸고 외부 호출은 나중에 하는 CEI 순서 + OpenZeppelin `ReentrancyGuard` |
| 같은 주문의 이중 체결 | 판매자별 `nonceUsed` 매핑, `minNonce`로 이전 주문 일괄 취소 |
| Fee-on-Transfer 토큰 | 전송 전후 잔액을 비교해 약속한 금액과 1이라도 다르면 되돌림 (`FoTDetected`) |
| 다른 체인에서 서명 재사용 | 배포 시 Chain ID를 고정하고 호출 때마다 비교 (`BadChain`) |
| 컨트랙트 지갑 판매자 | 판매자가 컨트랙트면 ERC-1271 `isValidSignature`로 검증 |
| 소유권 오이전 | `Ownable2Step`으로 새 소유자가 수락해야 이전 완료 |
| 운영 중 이상 상황 | 거래·취소를 각각 멈출 수 있는 스위치 (`setTradingPaused`, `setCancelPaused`) |

## 테스트

원본 프로젝트에서 Foundry로 테스트를 작성했습니다(테스트 함수 459개). 테스트는 기법별로 나눴습니다.

- 단위 테스트
- 페어와이즈 조합
- 상태 전이
- 다중 사용자 시나리오
- 에러 추측 기반 공격
- 엣지 케이스

테스트 코드는 회사 저장소에 있어 이 저장소에는 포함하지 않았습니다.
